# Запуск бенчмарков

Цели экспериментов и опубликованные результаты собраны в
[описании экспериментов](experiments.md). Здесь приведены команды запуска и
краткое пояснение к отчётам.

Для сборки требуется release-профиль и Cargo feature `stress-benchmark`.
Оконные прогоны выполняются в графической сессии с доступным адаптером.
Команды запускаются из корня репозитория.

## Масштабирование

Профиль [`stress-scaling.json`](configs/stress-scaling.json) проверяет сетку из
250–12 000 кубов. На каждый уровень отводится 3 секунды прогрева и 8 секунд
измерения; весь набор запускается трижды.

```bash
bash scripts/run-stress-scaling.sh
```

Отчёты сохраняются в `target/stress-scaling/`. Файл `summary.md` сводит FPS,
худшую полную секунду и p95 времени прохода. По умолчанию цель — 60 FPS; другое
значение задаётся переменной `BFGE_TARGET_FPS`, например:

```bash
BFGE_TARGET_FPS=90 bash scripts/run-stress-scaling.sh
```

Уровень проходит проверку, если средний FPS каждого запуска и FPS каждой полной
секунды не ниже цели. Это наибольший пройденный уровень из профиля, а не предел
производительности движка.

## Основной профиль

[`stress-baseline.json`](configs/stress-baseline.json) измеряет 1 000 кубов с
общим мешем: 10 секунд прогрева и 60 секунд измерения. Выполняются три запуска.

```bash
bash scripts/run-stress-baseline.sh
```

JSON-отчёты и сведения о запуске сохраняются в `target/stress-baseline/`.

## Диагностический профиль

Профиль [`stress-config.json`](configs/stress-config.json) сравнивает нагрузку
от числа объектов, глубины дерева, геометрии и отдельных мешей. Большинство
сцен измеряется 3 секунды после 2 секунд прогрева; длительная сцена — 60 секунд.

```bash
cargo run --release --locked --features stress-benchmark --bin bfge-stress -- scene-only benchmark/configs/stress-config.json target/stress-scene-only.json
cargo run --release --locked --features stress-benchmark --bin bfge-stress -- window benchmark/configs/stress-config.json target/stress-window.json
```

`scene-only` измеряет подготовку сцены без окна. `window` включает оконный цикл,
отправку графических команд и показ изображения. В обоих режимах измерение
начинается после подготовки сцены и прогрева.

## Чтение отчёта

- **FPS** — число завершённых проходов в секунду. При VSync значение зависит от
  частоты обновления дисплея.
- **p95 полного прохода** — время, за которое укладываются 95% проходов; рост
  этого показателя и падение FPS по отдельным секундам показывают просадки.
- **RSS** — оперативная память процесса; видеопамять в это значение не входит.

Полный проход измеряется на CPU и не включает ожидание завершения команд GPU.
Для сравнения результатов следует учитывать конфигурацию и сведения о системе,
которые сохраняются рядом с JSON-отчётами.
