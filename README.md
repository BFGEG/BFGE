# BFGE Engine

Blazingly Fast Graphic Engine — графический движок на Rust для desktop-приложений.
Движок владеет окном и циклом отображения; клиент загружает модели, строит сцену
и изменяет её через публичный API и обработчики кадра.

![Демонстрация отрисовки вращающихся кубов в BFGE](docs/bfge_demo.gif)

Сейчас реализованы:

- дерево узлов с наследуемыми положением, поворотом и масштабом;
- загрузка статических моделей OBJ, glTF 2.0 и GLB;
- отрисовка мешей через wgpu с depth-тестом и цветом модели;
- фоновое освещение и один направленный источник света для всей сцены;
- одна перспективная точка обзора;
- `frame_started` и `frame_ended`, обработка закрытия и изменения размера окна;
- сохранение и восстановление снимка сцены в памяти движка.

## Требования

- Rust **1.95.0** с Cargo — версия CI и проверок этого руководства. Минимальная
  поддерживаемая версия отдельно не установлена; крейт использует edition 2024.
  Для проверок нужны компоненты `rustfmt` и `clippy`.
- Git, системный linker и средства сборки: на Linux — C toolchain, на Windows —
  MSVC Build Tools для MSVC target, на macOS — Xcode Command Line Tools.
- Оконный код рассчитан на desktop Linux (X11/Wayland), Windows и macOS.
  Текущая CI проверяет Ubuntu; оконные smoke-тесты предусмотрены для Linux и Windows.
  Проверки на Linux не подтверждают работоспособность на остальных платформах.
  Web и мобильные платформы текущим циклом не поддерживаются.
- Для графических примеров нужны активная оконная сессия и доступный wgpu-адаптер
  с драйвером, поддерживающим показ кадра в окне. На Linux нужны библиотеки
  выбранной оконной системы, `libxkbcommon` и подходящий графический драйвер
  (обычно Vulkan). Обычные тесты не требуют дисплея или GPU.

Установка toolchain через [rustup](https://rustup.rs/):

```bash
rustup toolchain install 1.95.0 --profile minimal --component rustfmt --component clippy
```

## От клонирования до вращающейся модели

```bash
git clone https://github.com/BFGEG/BFGE.git
cd BFGE
rustup override set 1.95.0
cargo build --locked
cargo run --locked --example rotating_model
```

Пример использует включённый в репозиторий
[`examples/assets/cube.obj`](examples/assets/cube.obj): отдельная модель не нужна.
Появится окно 800 × 600 с вращающимся кубом. Можно менять размер окна,
сворачивать и восстанавливать его; закрытие окна завершает цикл и вызывает
освобождение движка в примере.

Запуск с собственной моделью:

```bash
cargo run --locked --example rotating_model -- path/to/model.gltf
```

[`rotating_model`](examples/rotating_model.rs) загружает OBJ,
glTF или GLB и изменяет преобразование узла в `frame_started`. Пути аргументов
отсчитываются от текущего рабочего каталога. Масштаб модели и точку обзора
при необходимости настраивает клиент. На Linux с доступным X11 и некорректным
Wayland-окружением можно запускать через
`env -u WAYLAND_DISPLAY -u WAYLAND_SOCKET cargo run --locked --example rotating_model`.

## Освещение и демонстрации

Чтобы увидеть работу света на неподвижных кубах:

```bash
cargo run --locked --example lighting_demo
```

Направленный свет обходит сцену примерно за восемь секунд. Грани кубов
поочерёдно светлеют и темнеют; плоскость остаётся освещённой сверху.

Настройка света до запуска и в обработчике кадра описана в
[руководстве пользователя](docs/User_Guide.md#освещение).
Другие [сценарии](examples/README.md) показывают пролёт над городом, вращающуюся
спираль и коридор с арками.

## Сборка, проверки и Rustdoc

Команды выполняются из корня репозитория:

```bash
cargo build --locked
cargo build --examples --locked
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo test --workspace --all-features --locked
cargo test --doc --locked
cargo doc --no-deps --all-features --locked
```

Rustdoc появится в `target/doc/BFGE/index.html`; открыть его в браузере можно
командой `cargo doc --no-deps --open`. Обычный набор тестов пропускает оконные тесты.
Команды отдельных проверок окна/GPU и ручной сценарий описаны в
[описании backend](docs/Wgpu_Backend.md#проверка-настоящей-поверхности).

## Ограничения

Версия 0.1.0 рассчитана на одну сцену, одну точку обзора и окно движка.
Нет публичных операций удаления/скрытия объектов, перепривязки узлов, ввода
с клавиатуры/мыши, управления отдельными кадрами или offscreen-вывода.
Обработчики получают только сцену; они не могут вызвать `shutdown()` или
изменить окно через `EngineApi`. `run()` блокирует поток до закрытия окна
или ошибки; после него нужен явный `shutdown()`.

Загрузка поддерживает статическую треугольную геометрию и один цвет на всю модель.
Текстуры, тени, анимация glTF, skinning и morph targets не реализованы;
сохранение не записывает файл и теряется при уничтожении `Engine`. Полные
[ограничения форматов](docs/User_Guide.md#загрузка-моделей) и
[правила снимков](docs/User_Guide.md#сохранение-и-восстановление-сцены) описаны
в руководстве.
