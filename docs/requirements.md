# Требования к BFGE

Документ фиксирует назначение и проверяемое поведение текущей версии BFGE.
Требования сгруппированы по уровням: цель продукта, задачи клиентского
разработчика, функции движка и характеристики качества. Реализация и связи
между подсистемами описаны в [архитектурном обзоре](architecture.md).

## Цель продукта

**BR-1.** BFGE должна предоставлять Rust-приложениям средства для подготовки и
отображения и изменения 3D-сцены в настольном окне во время работы.

## Задачи клиента

| ID | Требование пользователя |
| --- | --- |
| UR-1 | Создать движок, настроить сцену и открыть окно для её отображения. |
| UR-2 | Организовать объекты в иерархию и управлять их положением, поворотом и масштабом через узлы сцены. |
| UR-3 | Загрузить модель из поддерживаемого файла и разместить её в выбранном узле. |
| UR-4 | Настроить точку обзора и освещение сцены. |
| UR-5 | Изменять сцену в ответ на последовательные кадры. |
| UR-6 | Сохранить состояние сцены на время жизни движка и восстановить его в следующей оконной сессии. |

## Функциональные требования

| ID | Требование к движку | Проверка |
| --- | --- | --- |
| FR-1 | Движок должен позволять подготовить CPU-состояние сцены до открытия окна. | Создать экземпляр, изменить сцену, затем инициализировать окно. |
| FR-2 | Движок должен создавать окно и выполнять цикл кадров до закрытия окна или возникновения ошибки. | Интеграционная проверка полного оконного цикла. |
| FR-3 | Сцена должна содержать корневой узел и позволять создавать дочерние узлы. | Проверить создание узла и связь с родителем. |
| FR-4 | Объект должен наследовать положение, поворот и масштаб узла, к которому он привязан. | Изменить преобразование узла и проверить подготовленные данные кадра. |
| FR-5 | Загрузка поддерживаемого файла должна добавлять геометрию в ресурсы и создавать связанный объект сцены. | Интеграционные проверки OBJ, glTF и GLB. |
| FR-6 | Ошибка загрузки модели должна оставлять сцену и ресурсы без изменений. | Проверить неподдерживаемый формат, повреждённый файл и неизвестный узел. |
| FR-7 | Клиент должен иметь возможность задавать точку обзора и общее освещение сцены. | Проверить чтение и изменение состояния сцены. |
| FR-8 | Обработчики начала кадра должны выполняться до подготовки кадра, а обработчики конца — после успешной попытки отображения. | Проверить порядок вызовов и видимость изменений по кадрам. |
| FR-9 | Ошибка обработчика должна завершать цикл кадров и передаваться клиенту. | Вернуть ошибку из обработчика и проверить результат `run`. |
| FR-10 | Сохранение должно заменять снимок копией состояния сцены; восстановление должно возвращать его в свободную сцену. | Сохранить, завершить сессию, повторно открыть окно и восстановить состояние. |
| FR-11 | Завершение сессии должно освобождать оконные ресурсы и сбрасывать сцену, сохраняя снимок и зарегистрированные обработчики в экземпляре движка. | Проверить повторную инициализацию и восстановление снимка. |
| FR-12 | Обработчики кадров должны позволять загружать модели, создавать экземпляры с общей геометрией, удалять объекты и изменять их преобразования через узлы без перестройки иерархии. | Проверить изменения в текущем и следующем кадре, ошибки загрузки и недействительность удалённых ID. |
| FR-13 | Снимок должен сохранять живые объекты и недействительность удалённых ID; сцена после удаления всех объектов должна допускать восстановление. | Проверить сохранение с удалёнными объектами и восстановление в освободившуюся сцену. |

## Требования к качеству

| ID | Характеристика | Критерий проверки |
| --- | --- | --- |
| QR-1 | **Корректность состояния.** Операции сцены и загрузки должны проверять входные данные и сообщать об ошибках через типизированный результат. | Проверить успешные операции, ошибочные входные данные и сохранение состояния при ошибке. |
| QR-2 | **Разделение ответственности.** Состояние сцены и геометрия ресурсов должны передаваться в отображение через границу подготовки кадра. | Проверить архитектурные зависимости модулей и тесты подготовки кадра. |
| QR-3 | **Воспроизводимость измерений.** Нагрузочный запуск должен сохранять конфигурацию, результат и сведения о системе и ревизии. | Запустить профиль из `benchmark/` и проверить созданный отчёт и метаданные. |
| QR-4 | **Документированность клиентского поведения.** Публичные операции должны иметь Rustdoc, а пользовательские действия и ограничения входных данных — быть описаны в документации. | Проверить Rustdoc и сопоставить документацию с интеграционными тестами. |

Проверки оконного цикла требуют графической сессии и адаптера; команды приведены
в [описании отображения](graphics.md#проверка-с-окном-и-gpu). Методика
производительных измерений и доступные результаты находятся в
[разделе бенчмарков](../benchmark/experiments.md).
