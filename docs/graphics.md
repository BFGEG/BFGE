# Отображение сцены

Графическая часть преобразует подготовленную сцену в изображение окна. Она
получает кадр от движка, использует геометрию моделей и передаёт команды
графическому устройству. Настройка сцены со стороны приложения описана в
[руководстве пользователя](user-guide.md).

## Подготовка графической системы

При запуске сессии графическая система подготавливается в следующем порядке:

1. Создать окно и связанную с ним графическую поверхность.
2. Выбрать адаптер и подготовить устройство с очередью команд.
3. При первом кадре создать графический конвейер и буферы геометрии.
4. Сохранить буферы мешей в кэше для повторного использования.

При изменении размера окна поверхность и буфер глубины настраиваются под новый
размер. Свёрнутое окно приостанавливает отрисовку до восстановления его размера.

## Отображение кадра

Для каждого кадра графическая система выполняет следующие действия:

1. Получить доступный кадр поверхности; при необходимости восстановить её
   конфигурацию и повторить получение.
2. Подготовить буфер глубины, а также данные точки обзора и освещения.
3. Для каждого объекта передать его преобразование, цвет и геометрию. Создать
   буферы меша при первом использовании либо взять их из кэша.
4. Отправить команды отрисовки частей меша.
5. Завершить графический проход и передать изображение окну.

Поверхности модели отображаются треугольниками с проверкой глубины. Нормали
рассчитываются по треугольникам и усредняются для вершин с общими индексами.
Поэтому способ разделения вершин в исходной модели влияет на сглаживание.

## Освещение

Вся сцена использует фоновое освещение и один направленный источник. Цвет модели
умножается на сумму фоновой и диффузной составляющих. Диффузная составляющая
зависит от угла между нормалью поверхности и направлением света. При подготовке
кадра направление нормали согласуется с преобразованием объекта.

## Изменение размера и состояние поверхности

При явном изменении размера выполняются следующие действия:

1. Проверить размер по ограничениям графического устройства.
2. Настроить поверхность и буфер глубины.
3. Применить размер к окну.

Если настройка поверхности завершается ошибкой, действующая конфигурация
сохраняется. События изменения размера от окна применяются до подготовки
следующего кадра.

Кратковременная недоступность поверхности пропускает текущий кадр. Устаревшая
конфигурация обновляется, а потерянная поверхность создаётся заново. Ошибки
создания устройства, настройки поверхности и графических операций возвращаются
клиенту как ошибки отображения.

При завершении сессии освобождаются окно, поверхность, графический конвейер и
буфер глубины. Кэш мешей остаётся у графической системы и используется при
следующей инициализации.

## Проверка с окном и GPU

Для следующих проверок нужна активная графическая сессия и доступный адаптер.
Игнорируемые тесты создают поверхность, проверяют изменение размера,
минимизацию, восстановление и повторную инициализацию:

```bash
cargo test --lib platform::tests::native_surface_initializes_resizes_presents_and_reinitializes -- --ignored --exact --nocapture
```

Полный цикл движка с загрузкой модели и несколькими кадрами проверяется отдельно:

```bash
cargo test --lib core::engine::tests::native_engine_loads_model_and_drives_frames -- --ignored --exact --nocapture
```

На Linux с активной X11-сессией при необходимости можно очистить переменные
окружения Wayland перед запуском команды.
