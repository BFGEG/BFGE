# Руководство пользователя BFGE

Руководство описывает текущий API с циклом отображения из
[PR #45](https://github.com/BFGEG/BFGE/pull/45). Сборка репозитория и первый запуск
описаны в [README](../README.md), сигнатуры — в [справочнике API](FREAK_Engine_Public_API.md),
внутреннее устройство — в [архитектуре](FREAK_Engine_Architecture.md).

## Подключение к приложению

Используйте Rust 1.95.0 и локальный checkout BFGE с этой версией API. Для структуры:

```text
workspace/
├── BFGE/
└── bfge-client/
    ├── Cargo.toml
    └── src/main.rs
```

создайте клиент командой `cargo new bfge-client` из `workspace/` и добавьте
в его `Cargo.toml`:

```toml
[dependencies]
BFGE = { path = "../BFGE" }
```

Имя пакета и крейта — `BFGE`, с заглавными буквами. Для методов `Engine` нужно
импортировать `EngineApi`; при работе через `&mut dyn SceneApi` отдельно
импортировать `SceneApi` не требуется. `Vec3`, `Quat` и `Mat4` доступны через
`BFGE::math`, отдельная зависимость от `glam` для этих типов не нужна.

## Окно и жизненный цикл

Поместите этот код в `bfge-client/src/main.rs` и выполните `cargo run` из клиента:

```rust,no_run
use std::error::Error;

use BFGE::{Engine, EngineApi, WindowDescriptor};

const WINDOW_TITLE: &str = "My BFGE application";

fn main() -> Result<(), Box<dyn Error>> {
    let mut engine = Engine::new();
    engine.initialize(WindowDescriptor::new(WINDOW_TITLE, 800, 600))?;
    let result = engine.run();
    let shutdown = engine.shutdown();
    result?;
    shutdown?;
    Ok(())
}
```

Откроется окно с пустой сценой; закройте его для завершения программы. Такой же
сценарий в репозитории: `cargo run --locked --example minimal`.

`Engine::new()` собирает движок без окна/GPU: доступны корневой узел, точка
обзора, загрузка моделей, регистрация обработчиков и снимки. `initialize` создаёт
окно и графику, сохраняя подготовленную сцену. Ширина и высота задаются ненулевыми
размерами в физических пикселях. Оконные операции выполняются на главном потоке.

`run()` блокирует поток и сам вызывает обработчики и рендер. Закрытие окна
завершает `run()`, но ресурсы освобождаются при `shutdown()`. Пример вызывает
`shutdown()` до проверки результата цикла, поэтому освобождение выполняется
и при ошибке. Если ошиблись оба вызова, возвращается первичная ошибка `run()`;
при необходимости приложение может отдельно записать ошибку `shutdown` в журнал.

Повторная инициализация активного движка возвращает `AlreadyInitialized`.
`run()`, изменение размера и `shutdown()` без активной сессии возвращают
`NotInitialized`. Shutdown сбрасывает сцену и ресурсы; снимок, обработчики
и оконный цикл сохраняются. Используйте тот же `Engine` для следующей сессии:
winit разрешает создать только один оконный цикл на процесс.

Размер между `initialize` и `run` меняется через
`engine.set_window_size(BFGE::WindowSize::new(1280, 720))?`. Сначала проверяется
и перенастраивается backend, затем запрашивается изменение окна. Во время
`run()` resize окна обрабатывается автоматически. Нулевой размер из события
минимизации приостанавливает кадры; явный запрос нулевого размера возвращает ошибку.

## Узлы, объекты и преобразования

Узел хранит локальное преобразование и дочерние узлы. Объект — загруженная
модель, привязанная к одному узлу. Несколько объектов одного узла получают
одинаковую мировую матрицу. Каждая загрузка создаёт новый объект, даже для
составной модели или повторного пути.

Фрагменты с функциями ниже самостоятельны; при объединении в одном файле
объедините их импорты `use`. Вызовите `prepare_scene` после `Engine::new`,
до `initialize`, передав путь к модели: ошибка подготовки завершит программу
до открытия окна.

```rust,no_run
use std::error::Error;
use std::path::Path;

use BFGE::math::{Quat, Vec3};
use BFGE::{Engine, EngineApi, SceneNodeId, Transform, ViewpointState};

fn prepare_scene(engine: &mut Engine, path: &Path) -> Result<SceneNodeId, Box<dyn Error>> {
    let root = engine.scene().root_node();
    let group = engine.scene().create_node(root)?;
    let model_node = engine.scene().create_node(group)?;
    engine.scene().set_node_transform(group, Transform {
        translation: Vec3::new(1.0, 0.0, 0.0),
        rotation: Quat::from_rotation_y(0.5),
        scale: Vec3::splat(0.5),
    })?;
    let object = engine.load_model(path, model_node)?;
    let other_node = engine.scene().create_node(root)?;
    engine.scene().set_node_transform(
        other_node,
        Transform::from_translation(Vec3::new(-1.0, 0.0, 0.0)),
    )?;
    engine.scene().reparent_object(object, other_node)?;
    engine.scene().set_viewpoint(ViewpointState {
        position: Vec3::new(0.0, 1.0, 5.0),
        direction: Vec3::new(0.0, -1.0, -5.0),
        fov_y: 60.0_f32.to_radians(),
    })?;
    Ok(other_node)
}
```

Мировая матрица — `parent_world * local`; локальная применяет масштаб, поворот
и перенос в таком порядке. Преобразование корня влияет на всю иерархию.
`set_node_transform` заменяет все три компонента: `Transform::from_rotation`
также сбросит перенос и масштаб. Храните полный `Transform` в клиенте, чтобы
изменять одну компоненту. `Transform::from_euler` принимает радианы в порядке XYZ.

`reparent_object` переносит только объект: он сразу наследует новый узел,
прежняя мировая позиция не сохраняется. В примере модель перестаёт наследовать
`group`. Перепривязки узлов, удаления и скрытия объектов в API нет. ID непрозрачны
и относятся к текущей сцене. После сброса они могут совпасть с ID новых объектов:
проверок поколения нет.

## Точка обзора

Точка обзора независима от узлов. `scene.viewpoint()` возвращает её копию,
`scene.set_viewpoint(state)` заменяет состояние. По умолчанию позиция — `(0, 0, 5)`,
направление — `(0, 0, -1)`, вертикальный угол обзора — 60°. Направление является
вектором, а не координатами цели: для взгляда на `target` используйте
`target - position`.

Система координат правая, `+Y` направлена вверх. `fov_y` задаётся в радианах;
меньший угол приближает изображение. Aspect ratio следует размеру окна,
плоскости отсечения фиксированы на 0.1 и 100 единицах. Передавайте конечные числа,
ненулевое направление, не параллельное `+Y`, и `0 < fov_y < π`; quaternion
преобразования должен быть нормализован. Сеттеры сейчас сохраняют численные
значения без проверки: успешный `Result` не подтверждает корректность камеры.

## Обработчики кадра и EventTime

Вызовите `animate(&mut engine, node)?` перед `run()`, где `node` — узел модели,
например результат `prepare_scene`:

```rust
use std::f32::consts::TAU;

use BFGE::math::{Quat, Vec3};
use BFGE::{Engine, EngineApi, EngineError, EngineEvent, SceneNodeId, Transform};

fn animate(engine: &mut Engine, node: SceneNodeId) -> Result<(), EngineError> {
    let mut angle = 0.0;
    let mut transform = Transform::from_translation(Vec3::new(-1.0, 0.0, 0.0));
    engine.add_event(EngineEvent {
        frame_started: Box::new(move |scene, time| {
            angle = (angle + time.time_since_last_frame) % TAU;
            transform.rotation = Quat::from_rotation_y(angle);
            scene.set_node_transform(node, transform)
        }),
        frame_ended: Box::new(|_, _| Ok(())),
    })
}
```

Здесь перенос сохраняется при обновлении поворота. Готовый запускаемый пример —
[`rotating_model.rs`](../examples/rotating_model.rs).

Для событий A и B кадр выполняется как
`A.frame_started → B.frame_started → сборка/рендер → A.frame_ended → B.frame_ended`.
Изменения в начале попадают в текущий кадр; в конце — в следующий. `frame_ended`
означает успешный возврат рендера: при timeout/перекрытии backend может пропустить
показ. Ошибка рендера пропускает `frame_ended`.

Оба поля `EventTime` измеряются в секундах (`f32`):

| Поле | Значение |
| --- | --- |
| `time_since_last_event` | Интервал с предыдущего вызова любого обработчика; для первого — с запуска цикла. |
| `time_since_last_frame` | Интервал между началами кадров, одинаковый у всех обработчиков кадра; для первого — с запуска цикла. |

Для анимации используйте `time_since_last_frame`. При нулевом размере окна обе
фазы и рендер приостановлены, но события окна принимаются. Время минимизации
включается в интервал первого кадра после восстановления; при необходимости
ограничьте шаг в приложении. Ожидание между проходами рассчитано на бюджет
1/60 секунды, но фиксированная частота не гарантируется.

Обработчик — принадлежащий движку `Box<dyn FnMut(...) -> Result<(), SceneError>>`.
`move` переносит собственное состояние в замыкание; захваченные заимствования
должны быть `'static`. Обработчик получает только `&mut dyn SceneApi` и
`&EventTime`: доступа к загрузке моделей, окну или команде остановки из него нет.
Регистрация доступна до инициализации, отмены регистрации нет. Обработчики
переживают shutdown: перед следующим запуском обеспечьте актуальность ID,
например восстановив соответствующий снимок, и учитывайте сохранённое
в замыканиях состояние анимации.

## Загрузка моделей

`engine.load_model(path, parent)` доступен без окна. Относительный путь считается
от рабочего каталога процесса. Успех возвращает новый `SceneObjectId`; ошибка
оставляет сцену и ресурсы без изменений. Расширения нечувствительны к регистру.

| Формат | Поддерживается | Ограничения |
| --- | --- | --- |
| glTF 2.0 / GLB | Статические triangle primitives, преобразования узлов, геометрия с индексами или без; внешние относительные и base64-буферы, бинарный блок GLB. Выбранная сцена или первая сцена документа. | Отклоняются sparse accessors, skinning, morph targets, обязательные расширения, другие режимы primitives, документ без сцены и сетевые буферы. Анимационные каналы не воспроизводятся. |
| OBJ | Треугольники, простые выпуклые плоские многоугольники, положительные/отрицательные индексы, объекты/группы и MTL. | Вогнутые/неплоские многоугольники, точки и линии отклоняются. Ссылка на недоступную MTL-библиотеку вызывает ошибку; отсутствие ссылки допустимо. |

Все части модели используют первый явно заданный цвет используемого материала
в порядке обхода геометрии: glTF `baseColorFactor` или OBJ/MTL `Kd` с необязательным
`d`. Неиспользуемые материалы не влияют на цвет. По умолчанию — linear RGBA
`[0.8, 0.8, 0.8, 1.0]`. Текстуры, освещение и полноценная прозрачность
не реализованы: pipeline не включает alpha blending.

Геометрия должна содержать корректные треугольники с конечными координатами,
цвет — конечные компоненты в `[0, 1]`. Масштабирование под окно, центрирование
и автонастройка камеры не выполняются. Полные правила импорта описаны
в [архитектуре, §18.2](FREAK_Engine_Architecture.md#182-импорт-моделей).

## Сохранение и восстановление сцены

`save_scene()` заменяет единственный снимок в памяти `Engine`. Он включает
дерево узлов, преобразования, привязки объектов, геометрию/цвет мешей и точку
обзора. Окно, обработчики и захваченные ими данные не сохраняются. Снимок
переживает shutdown, но теряется при уничтожении движка; файла сохранения нет.
Текущее сохранение в памяти не имеет пути к ошибке.

Типовой переход между сессиями для уже инициализированного движка после `run()`:

```rust,no_run
use std::error::Error;

use BFGE::{Engine, EngineApi, WindowDescriptor};

const WINDOW_TITLE: &str = "Restored BFGE scene";

fn show_snapshot_in_new_session(engine: &mut Engine) -> Result<(), Box<dyn Error>> {
    engine.save_scene()?;
    engine.shutdown()?;
    engine.initialize(WindowDescriptor::new(WINDOW_TITLE, 800, 600))?;
    let result = engine.restore_scene()
        .map_err(Box::<dyn Error>::from)
        .and_then(|()| engine.run().map_err(Box::<dyn Error>::from));
    let shutdown = engine.shutdown();
    result?;
    shutdown?;
    Ok(())
}
```

Восстановление допускается, если в текущей сцене нет объектов; одни узлы
допустимы. Снимок целиком заменяет текущие узлы, ресурсы и точку обзора.
При занятой сцене возвращается `SceneNotEmpty`, даже если снимка нет. Если сцена
свободна, а снимка нет, вызов успешен и ничего не меняет. Проверка снимка идёт
до замены; ошибка сохраняет текущую сцену. Поскольку API не удаляет объекты,
сбросить занятую сцену можно завершением активной сессии. Восстановление
не сбрасывает угол вращения и другие данные прежних обработчиков.

## Ошибки

Ошибки реализуют `std::error::Error` и доступны из корня крейта. Цепочку причин
можно вывести так:

```rust
use std::error::Error;

fn report(error: &dyn Error) {
    eprintln!("{error}");
    let mut source = error.source();
    while let Some(cause) = source {
        eprintln!("caused by: {cause}");
        source = cause.source();
    }
}
```

| Операция | Ошибка и поведение |
| --- | --- |
| Окно, цикл, регистрация, shutdown | `EngineError`; ошибка обработчика становится `EngineError::Scene` с исходной причиной. |
| Узлы и объекты | `SceneError::UnknownNode` / `UnknownObject`. Численные значения преобразований и камеры сейчас не проверяются. |
| Загрузка | `ModelLoadError::Scene`, `UnsupportedFormat`, `Io { path, source }`, `Parse { path, message }`. Родитель проверяется до чтения файла. |
| Снимок | `ScenePersistenceError::SceneNotEmpty` / `Restore`; `Save` зарезервирован для будущих ошибок хранения. |

Типы ошибок отмечены `#[non_exhaustive]`: внешний `match` требует ветки `_`.
Ошибка обработчика немедленно завершает цикл; дальнейшие обработчики
не вызываются, изменения не откатываются. При любом возврате из `run()` флаг
работы и очередь сбрасываются, сцена и обработчики сохраняются.

## Проверка окна и GPU

Обычные тесты и doc-тесты не требуют дисплея. Компиляция примеров —
`cargo build --examples --locked`. Следующие тесты запускайте по одному
в оконной сессии Linux или Windows:

```bash
cargo test --locked --lib core::engine::tests::native_engine_loads_model_and_drives_frames -- --ignored --exact --nocapture
cargo test --locked --lib platform::tests::native_surface_initializes_resizes_presents_and_reinitializes -- --ignored --exact --nocapture
```

Первый загружает OBJ и выполняет три кадра через `Engine::run`, затем проверяет
ошибку обработчика и shutdown. Второй проверяет поверхность, resize, нулевой
размер, восстановление и повторную инициализацию. Они завершаются сами.
Другой ignored-тест `native_surface_draws_indexed_meshes` интерактивный и требует
закрытия окна; запуск всех ignored-тестов одной командой не подходит для автоматики.

Для ручной проверки `cargo run --locked --example rotating_model` убедитесь,
что куб виден и вращается, измените размер, сверните/восстановите окно и закройте.
Отдельно запустите `minimal` и закройте пустое окно. При ошибке создания окна
проверьте сессию; при ошибке графики — драйвер и доступность адаптера.
Условия запуска и вариант выбора X11 приведены в [README](../README.md#требования).
