# Руководство пользователя BFGE

Руководство описывает текущий API. Сборка репозитория и первый запуск
описаны в [README](../README.md), сигнатуры — в [справочнике API](FREAK_Engine_Public_API.md),
внутреннее устройство — в [архитектуре](FREAK_Engine_Architecture.md).

## Подключение к приложению

Для подключения движка к приложению:

1. Установить Rust 1.95.0 и клонировать репозиторий BFGE с этой версией API.
2. В каталоге рядом с BFGE создать клиент командой `cargo new bfge-client`.
   Получится следующая структура:

   ```text
   workspace/
   ├── BFGE/
   └── bfge-client/
       ├── Cargo.toml
       └── src/main.rs
   ```

3. Добавить зависимость в `bfge-client/Cargo.toml`:

   ```toml
   [dependencies]
   BFGE = { path = "../BFGE" }
   ```

4. Поместить код запуска в `bfge-client/src/main.rs`:

   ```rust,no_run
   use std::error::Error;

   use BFGE::{Engine, EngineApi, WindowDescriptor};

   const WINDOW_TITLE: &str = "My BFGE application";

   fn main() -> Result<(), Box<dyn Error>> {
       let mut engine = Engine::new();
       engine.initialize(WindowDescriptor::new(WINDOW_TITLE, 800, 600))?;
       let result = engine.run();
       let shutdown = engine.shutdown();
       result?;
       shutdown?;
       Ok(())
   }
   ```

5. Выполнить `cargo run` из каталога `bfge-client`. Откроется окно с пустой сценой.
   Закрытие окна завершит программу.

## Окно и жизненный цикл

Чтобы запустить движок:

1. Создать экземпляр через `Engine::new()`. До открытия окна доступны подготовка
   сцены, загрузка моделей, регистрация обработчиков и работа со снимками.
2. Инициализировать движок методом `initialize`, передав заголовок и размер окна.
   Подготовленная сцена сохраняется. Ширина и высота задаются ненулевыми размерами
   в физических пикселях. Оконные операции выполняются на главном потоке.
3. Запустить отображение методом `run()`. Он блокирует поток до закрытия окна
   или ошибки и вызывает обработчики кадра во время работы.
4. Освободить ресурсы методом `shutdown()` после возврата из `run()`, в том числе
   при ошибке. В коде выше освобождение выполняется до проверки результата цикла.
   Если оба метода возвращают ошибку, приложение возвращает ошибку `run()`;
   ошибку освобождения при необходимости можно отдельно записать в журнал.

Повторная инициализация активного движка возвращает ошибку `AlreadyInitialized`.
`run()`, изменение размера и `shutdown()` без активной сессии возвращают
ошибку `NotInitialized`. Завершение сессии сбрасывает сцену и загруженные модели;
снимок и обработчики сохраняются.

Чтобы начать следующую сессию:

1. Завершить текущую сессию через `shutdown()`.
2. Повторно инициализировать тот же экземпляр движка. Создание другого экземпляра
   для новой оконной сессии в том же процессе не поддерживается.
3. Подготовить сцену заново или восстановить снимок.
4. Запустить отображение и после его окончания освободить ресурсы.

Чтобы изменить размер окна между инициализацией и запуском, можно вызвать
`engine.set_window_size(BFGE::WindowSize::new(1280, 720))?`. Во время работы
изменения размера окна обрабатываются автоматически. При минимизации
отображение приостанавливается; явный запрос нулевого размера возвращает ошибку.

## Узлы, объекты и преобразования

Узел хранит локальное преобразование и дочерние узлы. Объект — загруженная
модель, привязанная к одному узлу. Несколько объектов одного узла получают
одинаковую мировую матрицу. Каждая загрузка создаёт новый объект, даже для
составной модели или повторного пути.

Для подготовки сцены перед открытием окна:

1. Создать экземпляр движка.
2. Вызвать `prepare_scene(&mut engine, path)`, передав путь к модели.
   Ошибка подготовки завершит программу до открытия окна.
3. Инициализировать движок, запустить отображение и после его окончания
   освободить ресурсы, как в примере выше.

```rust,no_run
use std::error::Error;
use std::path::Path;

use BFGE::math::{Quat, Vec3};
use BFGE::{Engine, EngineApi, SceneNodeId, Transform, ViewpointState};

fn prepare_scene(engine: &mut Engine, path: &Path) -> Result<SceneNodeId, Box<dyn Error>> {
    let root = engine.scene().root_node();
    let group = engine.scene().create_node(root)?;
    let model_node = engine.scene().create_node(group)?;
    engine.scene().set_node_transform(group, Transform {
        translation: Vec3::new(1.0, 0.0, 0.0),
        rotation: Quat::from_rotation_y(0.5),
        scale: Vec3::splat(0.5),
    })?;
    let object = engine.load_model(path, model_node)?;
    let other_node = engine.scene().create_node(root)?;
    engine.scene().set_node_transform(
        other_node,
        Transform::from_translation(Vec3::new(-1.0, 0.0, 0.0)),
    )?;
    engine.scene().reparent_object(object, other_node)?;
    engine.scene().set_viewpoint(ViewpointState {
        position: Vec3::new(0.0, 1.0, 5.0),
        direction: Vec3::new(0.0, -1.0, -5.0),
        fov_y: 60.0_f32.to_radians(),
    })?;
    Ok(other_node)
}
```

Мировая матрица — `parent_world * local`; локальная применяет масштаб, поворот
и перенос в таком порядке. Преобразование корня влияет на всю иерархию.
`set_node_transform` заменяет все три компонента: `Transform::from_rotation`
также сбросит перенос и масштаб. Для изменения одной компоненты нужно хранить
полный `Transform` в клиенте. `Transform::from_euler` принимает радианы в порядке XYZ.

`reparent_object` переносит только объект: он сразу наследует новый узел,
прежняя мировая позиция не сохраняется. В примере модель перестаёт наследовать
`group`. Перепривязки узлов, удаления и скрытия объектов в API нет. ID непрозрачны
и относятся к текущей сцене. После сброса сцены прежние ID нельзя использовать
для обращения к новым объектам.

## Точка обзора

Точка обзора независима от узлов. `scene.viewpoint()` возвращает её копию,
`scene.set_viewpoint(state)` заменяет состояние. По умолчанию позиция — `(0, 0, 5)`,
направление — `(0, 0, -1)`, вертикальный угол обзора — 60°. Направление задаёт,
куда смотрит камера: его компоненты показывают смещение по осям от камеры
к точке перед ней. Например, `(0, 0, -1)` означает взгляд вдоль отрицательной
оси Z. Чтобы направить камеру из `position` на точку `target`, нужно задать
`direction = target - position`. В примере выше камера находится в `(0, 1, 5)`
и смотрит в начало координат, поэтому направление равно `(0, -1, -5)`.

Система координат правая, `+Y` направлена вверх. `fov_y` задаётся в радианах;
меньший угол приближает изображение. Соотношение сторон определяется размером окна,
плоскости отсечения фиксированы на 0.1 и 100 единицах. Для корректного изображения
нужны конечные числа, ненулевое направление, не параллельное `+Y`, и
`0 < fov_y < π`; кватернион преобразования должен быть нормализован.
Успешное выполнение `set_viewpoint` не подтверждает корректность этих значений.

## Освещение

Вся сцена использует общее фоновое освещение и один направленный источник света.
Фоновый свет делает видимыми все поверхности, а направленный выделяет грани,
обращённые к источнику. По умолчанию фоновая интенсивность равна `(0.25, 0.25, 0.25)`,
направленная — `(0.75, 0.75, 0.75)`, лучи идут в направлении `(-0.5, -1, -0.5)`.
Тени, точечные источники и прожекторы не поддерживаются.

Чтобы настроить освещение:

1. Задать фоновую интенсивность, направление и интенсивность направленного света.
2. Передать настройки сцене до запуска отображения, например через
   `configure_lighting(&mut engine)?`:

   ```rust
   use BFGE::math::Vec3;
   use BFGE::{DirectionalLight, Engine, EngineApi, SceneError, SceneLighting};

   fn configure_lighting(engine: &mut Engine) -> Result<(), SceneError> {
       engine.scene().set_lighting(SceneLighting {
           ambient: Vec3::splat(0.2),
           directional: DirectionalLight {
               direction: Vec3::new(-1.0, -1.0, -0.5),
               color: Vec3::splat(0.8),
           },
       })
   }
   ```

3. Для изменения света во время работы вызвать `scene.set_lighting(...)`
   в обработчике кадра. `scene.lighting()` возвращает текущие настройки.

Направление показывает, куда идут лучи: `(0, -1, 0)` освещает сцену сверху вниз.
Его длина не задаёт яркость, нормализовать направление заранее не требуется.
Компоненты `ambient` и `color` задают интенсивность красного, зелёного и синего
света в линейном пространстве. Они должны быть конечными и неотрицательными;
значения выше единицы допустимы. Нулевой цвет отключает соответствующий свет.

Некорректное направление возвращает ошибку `SceneError::InvalidLightDirection`,
некорректная интенсивность — `SceneError::InvalidLightColor`. Направление должно
быть конечным, ненулевым и нормализуемым, даже при отключённом направленном свете.
При ошибке прежние настройки сохраняются. Освещение входит в снимок сцены.
Готовая анимация света — [`lighting_demo.rs`](../examples/lighting_demo.rs).

## Обработчики кадра

Для вращения модели:

1. Подготовить сцену и получить узел модели, например из `prepare_scene`.
2. Зарегистрировать обработчик вызовом `animate(&mut engine, node)?` до запуска
   отображения, где `node` — полученный узел.
3. Запустить отображение через `run()` и после его окончания освободить ресурсы.

```rust
use std::f32::consts::TAU;

use BFGE::math::{Quat, Vec3};
use BFGE::{Engine, EngineApi, EngineError, EngineEvent, SceneNodeId, Transform};

fn animate(engine: &mut Engine, node: SceneNodeId) -> Result<(), EngineError> {
    let mut angle = 0.0;
    let mut transform = Transform::from_translation(Vec3::new(-1.0, 0.0, 0.0));
    engine.add_event(EngineEvent {
        frame_started: Box::new(move |scene, time| {
            angle = (angle + time.time_since_last_frame) % TAU;
            transform.rotation = Quat::from_rotation_y(angle);
            scene.set_node_transform(node, transform)
        }),
        frame_ended: Box::new(|_, _| Ok(())),
    })
}
```

Здесь перенос сохраняется при обновлении поворота. Готовый запускаемый пример —
[`rotating_model.rs`](../examples/rotating_model.rs).

Обработчик `frame_started` подходит для изменения сцены перед отображением:
эти изменения видны в текущем кадре. Изменения в `frame_ended` видны в следующем.
Обработчики каждой фазы вызываются в порядке регистрации. Вызов `frame_ended`
не гарантирует, что кадр появился на экране; при ошибке отрисовки он не вызывается.

В примере угол вращения зависит от времени между кадрами
(`time_since_last_frame`, в секундах), поэтому скорость вращения не зависит
от частоты кадров. После восстановления свёрнутого окна этот интервал включает
время минимизации. Ограничение шага анимации в приложении позволяет избежать
резкого скачка модели.

В обработчике можно изменять сцену, но нельзя загружать модели, управлять окном
или останавливать движок. Обработчики сохраняются между сессиями вместе со своим
состоянием; отмены регистрации нет. Перед повторным запуском нужно восстановить
снимок с узлами, к которым обращаются обработчики, либо передать им актуальные ID.

## Загрузка моделей

`engine.load_model(path, parent)` доступен без окна. Относительный путь считается
от рабочего каталога процесса. Успех возвращает новый `SceneObjectId`; ошибка
оставляет сцену и ресурсы без изменений. Расширения нечувствительны к регистру.

| Формат | Поддерживается | Ограничения |
| --- | --- | --- |
| glTF 2.0 / GLB | Статические triangle primitives, преобразования узлов, геометрия с индексами или без; внешние относительные и base64-буферы, бинарный блок GLB. Выбранная сцена или первая сцена документа. | Отклоняются sparse accessors, skinning, morph targets, обязательные расширения, другие режимы primitives, документ без сцены и сетевые буферы. Анимационные каналы не воспроизводятся. |
| OBJ | Треугольники, простые выпуклые плоские многоугольники, положительные/отрицательные индексы, объекты/группы и MTL. | Вогнутые/неплоские многоугольники, точки и линии отклоняются. Ссылка на недоступную MTL-библиотеку вызывает ошибку; отсутствие ссылки допустимо. |

Все части модели используют первый явно заданный цвет используемого материала
в порядке обхода геометрии: glTF `baseColorFactor` или OBJ/MTL `Kd` с необязательным
`d`. Неиспользуемые материалы не влияют на цвет. По умолчанию — linear RGBA
`[0.8, 0.8, 0.8, 1.0]`. При отображении к цвету модели применяется
[освещение сцены](#освещение). Источники света из файла модели, текстуры
и полноценная прозрачность не поддерживаются.

Геометрия должна содержать корректные треугольники с конечными координатами,
цвет — конечные компоненты в `[0, 1]`. Масштабирование под окно, центрирование
и автонастройка камеры не выполняются. Полные правила импорта описаны
в [архитектуре, §18.2](FREAK_Engine_Architecture.md#182-импорт-моделей).

## Сохранение и восстановление сцены

`save_scene()` заменяет единственный снимок в памяти `Engine`. Он включает
дерево узлов, преобразования, привязки объектов, геометрию/цвет мешей, точку
обзора и освещение. Окно, обработчики и захваченные ими данные не сохраняются. Снимок
переживает завершение сессии, но теряется при уничтожении движка;
файла сохранения нет.

Типовой переход между сессиями для уже инициализированного движка после `run()`:

```rust,no_run
use std::error::Error;

use BFGE::{Engine, EngineApi, WindowDescriptor};

const WINDOW_TITLE: &str = "Restored BFGE scene";

fn show_snapshot_in_new_session(engine: &mut Engine) -> Result<(), Box<dyn Error>> {
    engine.save_scene()?;
    engine.shutdown()?;
    engine.initialize(WindowDescriptor::new(WINDOW_TITLE, 800, 600))?;
    let result = engine.restore_scene()
        .map_err(Box::<dyn Error>::from)
        .and_then(|()| engine.run().map_err(Box::<dyn Error>::from));
    let shutdown = engine.shutdown();
    result?;
    shutdown?;
    Ok(())
}
```

Восстановление допускается, если в текущей сцене нет объектов; одни узлы
допустимы. Снимок целиком заменяет текущие узлы, ресурсы, точку обзора и освещение.
При занятой сцене возвращается `SceneNotEmpty`, даже если снимка нет. Если сцена
свободна, а снимка нет, вызов успешен и ничего не меняет.
Ошибка восстановления сохраняет текущую сцену. Поскольку API не удаляет объекты,
сбросить занятую сцену можно завершением активной сессии. Восстановление
не сбрасывает угол вращения и другие данные прежних обработчиков.

## Ошибки

Ошибки реализуют `std::error::Error` и доступны из корня крейта. Цепочку причин
можно вывести так:

```rust
use std::error::Error;

fn report(error: &dyn Error) {
    eprintln!("{error}");
    let mut source = error.source();
    while let Some(cause) = source {
        eprintln!("caused by: {cause}");
        source = cause.source();
    }
}
```

| Операция | Ошибка и поведение |
| --- | --- |
| Окно, цикл, регистрация, shutdown | `EngineError`; ошибка обработчика становится `EngineError::Scene` с исходной причиной. |
| Узлы и объекты | `SceneError::UnknownNode` / `UnknownObject`. Численные значения преобразований и камеры сейчас не проверяются. |
| Освещение | `SceneError::InvalidLightDirection` / `InvalidLightColor`. Прежние настройки сохраняются при ошибке. |
| Загрузка | `ModelLoadError::Scene`, `UnsupportedFormat`, `Io { path, source }`, `Parse { path, message }`. Родитель проверяется до чтения файла. |
| Снимок | `ScenePersistenceError::SceneNotEmpty` / `Restore`; `Save` зарезервирован для будущих ошибок хранения. |

Типы ошибок отмечены `#[non_exhaustive]`: внешний `match` требует ветки `_`.
Ошибка обработчика немедленно завершает цикл; дальнейшие обработчики
не вызываются, изменения не откатываются. После возврата из `run()` сцена
и обработчики сохраняются.
