# Руководство пользователя BFGE

Руководство описывает основные этапы работы с движком и параметры сцены.
Подключение и первый запуск показаны в [корневом README](../README.md), полный
перечень действий API — в [справочнике](api.md), а сигнатуры и контракты методов —
в Rustdoc.

## Подключение

BFGE подключается как зависимость Cargo. Для локальной разработки укажите путь к
репозиторию в `Cargo.toml`; после сборки клиент получает доступ к библиотеке и
создаёт экземпляр движка. Краткий запускаемый вариант находится в примере
[`rotating_model`](../examples/rotating_model.rs).

## Оконная сессия

Работа с окном состоит из следующих шагов:

1. Создать движок и при необходимости заранее подготовить сцену.
2. Инициализировать движок с заголовком и ненулевым размером окна. Операцию
   выполнять на главном потоке.
3. Запустить цикл кадров. Он работает до закрытия окна или ошибки и блокирует
   текущий поток.
4. После возврата из цикла завершить сессию вызовом `shutdown`, в том числе если
   цикл вернул ошибку.

После завершения сессии тот же экземпляр движка можно инициализировать снова.
Для новой сессии сцена создаётся заново либо восстанавливается сохранённый
снимок. Обработчики кадров остаются зарегистрированными в экземпляре движка.
Размер окна задаётся в физических пикселях; изменение размера активного окна
обрабатывается движком.

## Построение сцены

Сцена содержит дерево узлов и объекты, привязанные к его узлам. Узел задаёт
локальное положение, поворот и масштаб относительно родителя. Итоговое
преобразование узла определяется всей цепочкой родителей. Объект наследует его
преобразование целиком.

Для построения иерархии:

1. Получить корневой узел сцены.
2. Создать дочерние узлы для группировки объектов.
3. Задать локальные преобразования нужных узлов.
4. Загрузить модели в выбранные узлы.

Замена преобразования узла задаёт все три компонента — положение, поворот и
масштаб. При изменении одного компонента следует сохранить и передать остальные.
Преобразование состоит из масштаба, поворота и переноса; углы, задаваемые через
Euler-представление, указываются в радианах. Перепривязанный объект наследует
преобразование нового узла.

## Точка обзора

Точка обзора настраивается отдельно от дерева узлов. По умолчанию камера
расположена в `(0, 0, 5)`, направлена вдоль отрицательной оси Z и использует
вертикальный угол обзора 60 градусов. Направление задаёт вектор от камеры к
точке, на которую она смотрит; чтобы навести камеру на `target`, использовать
разность `target - position`.

| Параметр | Правило |
| --- | --- |
| `position` | Положение камеры в координатах сцены. |
| `direction` | Конечный ненулевой вектор направления взгляда, не параллельный оси `+Y`. |
| `fov_y` | Вертикальный угол обзора в радианах, строго между 0 и π. |

Система координат правая, ось `+Y` направлена вверх. Соотношение сторон
рассчитывается по размеру окна, ближняя и дальняя плоскости отсечения находятся
на расстояниях 0,1 и 100 единиц.

## Освещение

Освещение задаётся для всей сцены: фоновая интенсивность и один направленный
источник. По умолчанию фоновая интенсивность равна `(0.25, 0.25, 0.25)`, цвет
источника — `(0.75, 0.75, 0.75)`, направление лучей — `(-0.5, -1, -0.5)`.

Компоненты цвета задаются в линейном RGB-пространстве, должны быть конечными и
неотрицательными; значения выше единицы допустимы. Направление показывает, куда
идут лучи, и должно быть конечным, ненулевым и нормализуемым. При ошибке прежние
настройки остаются активными. Настройки освещения входят в снимок сцены.

Для изменения света во время работы обновлять состояние сцены из обработчика
начала кадра. Пример анимированного освещения находится в
[`lighting_demo`](../examples/lighting_demo.rs).

## Обработчики кадров

Обработчики регистрируются до запуска цикла и вызываются в порядке регистрации.
Обработчик начала кадра выполняется перед подготовкой сцены, поэтому его
изменения видны в текущем кадре. Обработчик конца вызывается после успешной
попытки отображения; его изменения попадают в следующий кадр.

В обработчик передаётся время между кадрами и время между вызовами обработчиков,
оба значения — в секундах. Использовать интервал между кадрами для расчёта
анимации, чтобы её скорость не зависела от частоты кадров. Если обработчик
возвращает ошибку, цикл завершается, а уже внесённые изменения остаются в сцене.

Обработчики получают `FrameContext`: `context.scene()` даёт доступ к сцене,
`context.load_model(path, parent)` загружает модель. Результат обработчика —
`Result<(), EngineError>`; ошибки сцены и загрузки преобразуются через `?`.
При обновлении прежнего обработчика `|scene, time|` используйте
`|context, time|` и получите сцену вызовом `let scene = context.scene();`.
В конце обработчика верните `Ok(())` после вызовов с `?` либо преобразуйте
результат операции сцены через `.map_err(Into::into)`.

Обработчики сохраняют захваченное состояние на весь
срок жизни движка. Если сессии повторно используют сохранённые обработчики,
связанные с ними узлы следует восстановить либо получать актуальные ID из
разделяемого состояния. Пример анимации объекта находится в
[`rotating_model`](../examples/rotating_model.rs).

## Изменение объектов во время работы

Сцена сохраняет устройство «дерево узлов и привязанные к ним объекты».
В обработчике можно загружать модели, создавать экземпляры, удалять и
перепривязывать объекты, менять преобразования узлов, камеру и свет.
Чтобы работать с фиксированной иерархией, создайте нужные узлы до `run()` и
изменяйте их содержимое и преобразования в обработчиках.

```rust
use std::path::Path;
use BFGE::{Engine, EngineApi, EngineEvent, Transform};
use BFGE::math::Vec3;

let mut engine = Engine::new();
let root = engine.scene().root_node();
let node = engine.scene().create_node(root)?;
let mut object = None;
let mut elapsed = 0.0_f32;
engine.add_event(EngineEvent {
    frame_started: Box::new(move |context, time| {
        elapsed += time.time_since_last_frame;
        if object.is_none() && elapsed < 5.0 {
            object = Some(context.load_model(Path::new("model.obj"), node)?);
        }
        if elapsed >= 5.0 {
            if let Some(id) = object.take() {
                context.scene().remove_object(id)?;
            }
        }
        context.scene().set_node_transform(
            node,
            Transform::from_translation(Vec3::new(elapsed.sin(), 0.0, 0.0)),
        )?;
        Ok(())
    }),
    frame_ended: Box::new(|_, _| Ok(())),
})?;
```

Для повторяющихся объектов используйте `clone_object(source, parent)`: новый
объект наследует преобразование целевого узла и использует меш исходного.
Удаление исходного объекта не удаляет его экземпляры. Удалённый ID отклоняется
операциями сцены с `SceneError::UnknownObject` и не переиспользуется при
дальнейшем создании объектов. Удаление всех объектов позволяет восстановить
сохранённый снимок в ту же сцену.

Слоты удалённых ID сохраняются до сброса сцены. Удаление объекта не освобождает
ресурсы модели и GPU-кэш. CPU-ресурсы сбрасываются при завершении сессии,
GPU-кэш — при следующей инициализации backend или уничтожении движка. Повторная
загрузка файла создаёт новый ресурс, поэтому для одинаковой геометрии лучше
загрузить модель один раз и создавать экземпляры. Загрузка в обработчике
синхронная и может задержать кадр.

Примеры с заранее созданными узлами:
[`runtime_objects`](../examples/runtime_objects.rs) показывает появление,
движение и удаление экземпляров; [`runtime_model_loading`](../examples/runtime_model_loading.rs)
загружает модели по очереди во время `run()` и удаляет предыдущие объекты.

## Загрузка моделей

`load_model` загружает файл до или после инициализации окна, а через контекст
кадра — непосредственно во время `run()`. Относительные пути
считаются от рабочего каталога процесса, расширения распознаются без учёта
регистра. Каждый успешный вызов создаёт отдельный объект и ресурс геометрии.
Части составной модели объединяются в одном объекте сцены.

| Формат | Поддерживаемые данные |
| --- | --- |
| glTF 2.0 / GLB | Статические треугольные primitives, геометрия с индексами и без, преобразования узлов, внешние относительные и base64-буферы, бинарный блок GLB. Используется выбранная сцена или первая сцена документа. |
| OBJ | Треугольники и простые выпуклые плоские многоугольники, положительные и отрицательные индексы, объекты, группы и MTL. |

Все части модели используют один цвет. Выбирается первый явно заданный цвет
материала используемой геометрии: `baseColorFactor` в glTF или `Kd` в OBJ/MTL;
если цвет не задан, применяется линейный RGBA `(0.8, 0.8, 0.8, 1.0)`. На цвет
модели влияет освещение сцены.

## Сохранение и восстановление

Снимок хранится в памяти экземпляра движка и переживает завершение оконной
сессии. `save_scene` заменяет прежний снимок копией дерева узлов, объектов,
зарегистрированных ресурсов, точки обзора и освещения.

Чтобы продолжить работу со снимком:

1. Сохранить текущее состояние вызовом `save_scene`.
2. Завершить оконную сессию.
3. Инициализировать тот же экземпляр движка.
4. Восстановить сохранённое состояние вызовом `restore_scene`.
5. Запустить цикл кадров.

Восстановление заменяет содержимое сцены и доступно, когда в ней нет объектов.
При пустом хранилище вызов оставляет сцену без изменений. Снимок не содержит
данных окна, обработчиков и состояния, захваченного обработчиками.

## Ошибки

Публичные операции сообщают об ошибках через типизированные результаты.
Основные группы ошибок:

| Область | Причины |
| --- | --- |
| Окно и цикл кадров | Ошибка создания или настройки окна, вызов операции вне активной сессии, ошибка обработчика. |
| Сцена | Неизвестный узел или объект, некорректные параметры освещения. |
| Загрузка модели | Неподдерживаемый формат, ошибка чтения файла или буфера, некорректная геометрия, неизвестный родительский узел. |
| Снимок | Восстановление в сцену с объектами или некорректное сохранённое состояние. |

При ошибке загрузки модель не добавляется в сцену. Ошибки параметров освещения
сохраняют прежние настройки. Полные типы ошибок и поведение каждой операции
приведены в [справочнике API](api.md) и Rustdoc.
