# wgpu backend — текущее состояние

Реализация задачи #10 использует `wgpu 30`, `winit 0.30` и синхронное ожидание
инициализации GPU через `pollster`. Оконный адаптер рассчитан на desktop-платформы
с поддержкой `pump_app_events` в winit: Linux, Windows и macOS.

## Владение и инициализация

`Engine::initialize` создаёт окно через `PlatformAdapter`, затем вызывает
`systems::lifecycle::initialize`. Backend получает окно через `RenderSystem`,
создаёт совместимый адаптер, устройство, очередь и поверхность. Нативное окно
разделяется через `Arc`, поэтому поверхность не содержит висячую ссылку на окно.
Нативные оконные типы остаются внутри `platform` и backend.
После настройки поверхности backend создаёт mesh pipeline для WGSL-шейдера
из #13. Его вход — позиция и цвет вершины; две группы uniform-параметров
предназначены для матриц камеры и объекта и общего цвета модели.

Инициализацию движка нужно вызывать на главном потоке приложения. winit разрешает
создать только один цикл событий за время процесса; повторная инициализация
самого backend на существующем окне поддерживается.

## Кадр и изменение размера

- `render` получает меши по handles из `ResourceManager`, проверяет их и создаёт
  vertex/index buffers для каждого уникального меша кадра. Объекты с одним
  мешем разделяют эти буферы, но получают отдельные матрицы `world`.
- Каждый `SubMesh` рисуется через `draw_indexed`. После отправки команд вызывается
  `Queue::present`; `RenderStats` содержит число отправленных вызовов рисования
  и треугольников. Пропущенный из-за размера или недоступности поверхности кадр
  возвращает нулевую статистику.
- Каждый кадр очищает depth buffer значением 1.0. Pipeline настроен записывать
  глубину и выбирать ближний фрагмент при перекрытии геометрии.
- Некорректный handle или меш возвращает `RenderError` до показа кадра.
- GPU-буферы пока создаются заново для каждого кадра; постоянный кеш ресурсов
  требует отслеживания замены мешей между кадрами.
- `set_window_size` backend перестраивает конфигурацию поверхности. Нулевой размер
  при минимизации приостанавливает показ до следующего ненулевого размера.
  Depth buffer пересоздаётся под ненулевой размер и освобождается при минимизации.
- Явный запрос клиента на создание или изменение окна требует ненулевых размеров.
- Размер поверхности проверяется по лимиту устройства до конфигурирования.
- При явном resize движок сначала проверяет размер и перенастраивает backend,
  затем запрашивает изменение окна. Отказ backend не изменяет размер окна;
  при ошибке конфигурации сохраняется предыдущий целевой размер поверхности.
- При устаревшей поверхности конфигурация обновляется; при потере поверхности
  она создаётся заново. Получение кадра повторяется не более одного раза.
- Timeout и перекрытое окно пропускают кадр. Ошибки конфигурации, валидации,
  памяти и внутренних GPU-операций возвращаются через `RenderError`.
- `shutdown` освобождает состояние backend и допускает повторный вызов.

Главный цикл `Engine::run`, доставка событий закрытия/resize и вызовы обработчиков
кадра остаются задачей #15. Загрузка моделей и сборка кадров ещё содержат заглушки;
сквозной показ загруженной сцены в этой задаче не реализован.

## Проверка настоящей поверхности

Обычные тесты не требуют дисплея или GPU. На Linux и Windows отдельно доступен
тест, который открывает небольшое окно и проверяет инициализацию, рисование
двух кубов из одного меша, статистику, resize, минимизацию, восстановление,
shutdown и повторную инициализацию backend:

```bash
cargo test --lib platform::tests::native_surface_initializes_resizes_presents_and_reinitializes -- --ignored --exact --nocapture
```

Для него необходимы работающая оконная сессия и графический адаптер с поддержкой
показа кадра в окне. По умолчанию этот тест помечен `ignore` для CI без дисплея.

Для визуальной приёмки откройте окно с тремя кубами: два серых используют один
меш с разными преобразованиями, красный находится ближе к камере и перекрывает
их на изображении без пересечения в пространстве. Измените размер окна и
закройте его; тест проверит, что кадры показывались до и после изменения размера:

```bash
cargo test --lib platform::tests::native_cube_preview_renders_until_closed --locked -- --ignored --exact --nocapture
```

Отдельные тесты без окна считывают результат из GPU-текстуры: один проверяет
все части составного меша у двух объектов, другой — перспективу и перекрытие
треугольников с помощью depth buffer:

```bash
cargo test --lib backend::wgpu::surface::tests:: -- --ignored --nocapture
```
