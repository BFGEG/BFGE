# wgpu backend — текущее состояние

Реализация задачи #10 использует `wgpu 30`, `winit 0.30` и синхронное ожидание
инициализации GPU через `pollster`. Оконный адаптер рассчитан на desktop-платформы
с поддержкой `pump_app_events` в winit: Linux, Windows и macOS.

## Владение и инициализация

`Engine::initialize` создаёт окно через `PlatformAdapter`, используя цикл событий
(`winit::event_loop::EventLoop`), который принадлежит движку и переиспользуется
между сессиями. Затем он вызывает `systems::lifecycle::initialize`. Backend
получает окно через `RenderSystem`, создаёт совместимый адаптер, устройство,
очередь и поверхность. Нативное окно разделяется через `Arc`, поэтому поверхность
не содержит висячую ссылку на окно. Нативные оконные типы остаются внутри
`platform` и backend.

Инициализацию движка нужно вызывать на главном потоке приложения. winit разрешает
создать только один цикл событий за время процесса; цикл событий создаётся один
раз при первом `initialize` и сохраняется в `Engine` для следующих сессий.
Повторная инициализация самого backend на существующем окне поддерживается.

## Кадр и изменение размера

- `render` очищает поверхность, рисует индексированные меши с depth-тестом и
  вызывает `Queue::present`. `RenderStats` содержит число draw calls и треугольников.
- `set_window_size` backend перестраивает конфигурацию поверхности. Нулевой размер
  при минимизации приостанавливает показ до следующего ненулевого размера.
- Явный запрос клиента на создание или изменение окна требует ненулевых размеров.
- Размер поверхности проверяется по лимиту устройства до конфигурирования.
- При явном resize движок сначала проверяет размер и перенастраивает backend,
  затем запрашивает изменение окна. Отказ backend не изменяет размер окна;
  при ошибке конфигурации сохраняется предыдущий целевой размер поверхности.
- При устаревшей поверхности конфигурация обновляется; при потере поверхности
  она создаётся заново. Получение кадра повторяется не более одного раза.
- Timeout и перекрытое окно пропускают кадр. Ошибки конфигурации, валидации,
  памяти и внутренних GPU-операций возвращаются через `RenderError`.
- `shutdown` освобождает состояние backend и допускает повторный вызов.

`Engine::run` получает события через принадлежащий движку оконный цикл.
Resize применяется до следующего кадра; закрытие завершает `run`, после чего
клиент вызывает `shutdown`. Сборка кадра и загрузка OBJ/glTF/GLB реализованы.

## Проверка настоящей поверхности

Обычные тесты не требуют дисплея или GPU. На Linux и Windows отдельно доступен
тест, который открывает небольшое окно и проверяет инициализацию, resize,
минимизацию, восстановление, shutdown и повторную инициализацию backend:

```bash
cargo test --lib platform::tests::native_surface_initializes_resizes_presents_and_reinitializes -- --ignored --exact --nocapture
```

Для него необходимы работающая оконная сессия и графический адаптер с поддержкой
показа кадра в окне. По умолчанию этот тест помечен `ignore` для CI без дисплея.

## Пример через публичный API

```bash
cargo run --example rotating_model
cargo run --example rotating_model -- path/to/model.obj
```

Без аргумента используется `examples/assets/cube.obj`. Пример загружает модель,
вращает её в `frame_started` и освобождает движок после закрытия окна. Для ручной
проверки измените размер окна, сверните и восстановите его, затем закройте.

Автоматически завершающийся тест полного пути через `Engine::run` загружает OBJ,
выполняет три кадра и проверяет остановку по ошибке обработчика и shutdown:

```bash
cargo test --lib core::engine::tests::native_engine_loads_model_and_drives_frames -- --ignored --exact --nocapture
```

На Linux с доступным X11 и недоступным Wayland перед командой можно использовать
`env -u WAYLAND_DISPLAY -u WAYLAND_SOCKET`.
